# Bounded scripted institutional continuity fixture

Status: implemented as test fixtures; eight new tests and an uninterrupted reference pass within
198 continuity/related regression tests on 2026-09-06. This is the second finite foundation review
milestone in `pprl-complexity-review.md`. It composes existing contracts; it is not a general
scheduler, a model campaign, or evidence that persistence improves scientific performance.

## Boundary and task

A fresh, private SQLite institution owns one explicitly planned task: test the ordered divisors
2, 3, 5, 7, 11 and 13 of 221, retaining rejected hypotheses, then finish after finding a factor.
Two native scripted worker processes alternate actions. Each receives its own scoped credential
and only the existing allowlisted worker observation over inherited, addressed socket pairs.
The worker proposes `hypothesis_updated` until a supported hypothesis exists, then
`project_completed`. A trusted fixture executor validates this fixed action mask and computes
the public mathematical transition. It never interprets worker-controlled identifiers as actions
or imports a raw forensic tool result into state. Event costs are declared synthetic accounting;
there are no model tokens, real serving costs, training outcomes or parameter updates.

The task, initial state, original Amber authorization/resource grant, worker scope and finite
ownership plan are enrolled before dispatch. Replacement cannot create another task, rollout,
replica, grant, or fork. Scripted policy and all execution/fixture identities remain explicit.
The two registered workers are real separate processes, with process-local observations and
counters. Their entire roster and broker are discarded at restart. No old Python object, bearer
token, prompt cache or unfinished stack is a restart input.

## Trust and authority assumptions

The fixture controller, scripted worker code, broker, reviewer declaration, host user and local
database/artifact storage are trusted. Workers have an empty scratch working directory, a scrubbed
environment and explicitly inherited communication descriptors. This is **not an OS or secret
sandbox**: same-user filesystem access remains possible. A forensic canary can demonstrate that
the delivered interface omits privileged content and locators; it cannot attest physical isolation.
No network listener, model, container, GPU, cloud resource, credentials discovery, external tool,
communication fabric or delegated model hierarchy is introduced.

The trusted controller detects only its owned subprocess exit/EOF and bounded request deadlines.
It revokes the dead roster through the existing reviewer API, then performs reviewed recovery
against the exact current state, lease and original account. This fixed failure detector is not a
production heartbeat service. Normal state actions have no external effect; unfinished pure
computation before commit may be discarded and retried after reviewed unstarted release.

## Invariants and acceptance cases

- An uninterrupted reference and restarted runs finish with byte-equivalent public states and
  identical original-task charges. Five rejected candidates survive replacement; each committed
  candidate is tested once. Replay, ownership, observation and resource checks use production APIs.
- Every roster replacement revokes all old credentials before issuing fresh ones. Workers start
  with empty local counters and receive the exact current admitted state, not predecessor memory.
  Both members of every roster act; the fixture makes no concurrency or economic routing claim.
- Actual broker loss after claim, after admission, and inside the outer event transaction leaves
  the last committed state intact. Only untouched reservations are released. A crash after commit
  but before acknowledgement preserves the transition and charge and does not repeat the action.
- Explicit authority pause prevents dispatch; reviewed resume preserves the same state and budget.
  Repeated churn remains within finite task, action, worker, request, byte and lifetime bounds.
- A started effect lacking a known result retains its hold and requires terminal abandonment.
  A synthetically completed container result lacking an admitted state transition retains its
  charge and also requires terminal abandonment. These are independent stop probes, not recovery
  into new tasks. The synthetic container driver launches no physical container.
- Abandoned samples remain reconstructable and excluded by training compilation. Completion of
  the math fixture is not a registered domain outcome or training eligibility.
- Faults do not cause a permissive fallback, mint authority, expose private exception details,
  or execute an effect twice. Missing durable records or retained bytes fail closed.

## Evidence, failure and rollback

Retain the exact source and interpreter/script identities, fixture declarations, SQLite databases,
classified artifacts, immutable request/observation/action/recovery/task/abandonment lineage,
sanitized process identities, crash markers and exits, phase snapshots, public observation bytes,
independent assertions, account comparisons, compiler exclusions and cleanup results. Never retain
plaintext worker credentials or bootstrap messages. Fixed deterministic repeats are engineering
repeats, not independent stochastic research samples. Record observed runtime only as local fixture
timing, not capacity or long-horizon performance.

Initialize exclusively into a new scratch evidence directory; never create/drop a schema in an
arbitrary user database. Unexpected timeout, malformed frame, mask violation, missing evidence or
postflight failure stops that case and retains its evidence. Terminate and reap only subprocesses
owned by the fixture; preserve stopped financial holds. SQL rollback and reviewed recovery are the
rollback paths. Do not rewrite history or automatically retry an uncertain effect.

## Explicit non-goals and next review

No new production tables, wire schema, general worker launcher, dynamic task graph, general
continuing successor, effect retry policy, adversarial OS containment, message/delegation protocol,
model hierarchy, frontier escalation, Atlas experiment, trainer, consolidation or pruning is part
of this slice. Stop at the milestone review. Pilot trust assumptions and history-growth measurements
come next, followed by a concrete preregistered local Nemotron campaign under its execution gate.
Inkling comparison, mechanistic telemetry, 10M-plus-token rollouts and the full PPRL research program
remain later stages with their own evidence and authority requirements.
